
# Планировщик задач на Go

Веб-приложение для управления задачами. Позволяет создавать, просматривать, редактировать, выполнять и удалять задачи, а также настраивать их повторение.

Сервер написан на Go. Для хранения задач используется SQLite. Веб-интерфейс находится в директории `web`, тесты API — в директории `tests`.

## Дополнительные задания

Реализованы задания повышенной сложности:

- Поддержка переменных окружения `TODO_PORT` и `TODO_DBFILE`.
- Повторение задач по дням недели (`w`) и месяцам (`m`).
- Поиск задач по заголовку, комментарию и дате.
- Аутентификация с помощью JWT и переменной `TODO_PASSWORD`.
- Сборка и запуск приложения в Docker.

## Запуск приложения

Для запуска необходим установленный Go.

В корневой директории проекта выполните:

```bash
go run .
```

По умолчанию приложение доступно по адресу:

http://localhost:7540

При первом запуске создаётся база данных `scheduler.db`.

Можно изменить порт и путь к базе данных с помощью переменных окружения:

```bash
TODO_PORT=8080 TODO_DBFILE=scheduler.db go run .
```

Для включения аутентификации укажите пароль:

```bash
TODO_PASSWORD=12345 go run .
```

Страница входа:

http://localhost:7540/login.html

Если `TODO_PASSWORD` не задан или пустой, аутентификация не требуется.

## Тестирование

Запускайте тесты из корневой директории проекта при работающем сервере. Используйте отдельную базу данных, поскольку `TestTasks` удаляет задачи из базы, с которой работает тест.

Для проверки с авторизацией запустите сервер в первом терминале. Пароль `practicum-review-test` предназначен для локального тестирования.

```bash
TODO_PORT=17540 TODO_DBFILE=/tmp/go-final-project-review.db TODO_PASSWORD=practicum-review-test go run .
```

Во втором терминале запустите тесты с тем же портом и путём к базе.

```bash
TODO_PORT=17540 TODO_DBFILE=/tmp/go-final-project-review.db go test -count=1 ./tests
```

Для проверки без авторизации запустите сервер с пустым `TODO_PASSWORD` и повторите ту же команду тестов.

Параметры в `tests/settings.go`

- `Port = 7540` — порт сервера.
- `DBFile = "../scheduler.db"` — путь к базе данных.
- `FullNextDate = true` — проверка дополнительных правил повторения.
- `Search = true` — проверка поиска.
- `Token` — тестовый JWT без срока действия, подписанный паролем `practicum-review-test`. Токены, которые выдаёт `POST /api/signin`, действуют 8 часов.

## Docker

Из корневой директории проекта соберите Docker-образ. Docker сам компилирует приложение из исходников.

```bash
docker build -t go-scheduler:latest .
```

Создайте каталог для SQLite на компьютере и подключите его к контейнеру.

```bash
mkdir -p data
docker run --rm --name go-scheduler \
  -p 7541:7540 \
  -v "$(pwd)/data:/data" \
  go-scheduler:latest
```

Откройте [http://localhost:7541](http://localhost:7541). При первом запуске приложение создаст файл `data/scheduler.db` на компьютере. Задачи сохранятся при перезапуске контейнера.

При необходимости пароль можно передать контейнеру через параметр `-e TODO_PASSWORD=...`.
